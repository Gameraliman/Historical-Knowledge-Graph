# Historical Knowledge Graph Explorer

کاوشگر تعاملی گراف دانش تاریخی با رابط فارسی و پشتیبانی از نمایش و جست‌وجوی گراف در **Streamlit**. این پروژه از **Neo4j** برای نگهداری داده‌ها و از **Pyvis، Pandas و Plotly** برای نمایش و تحلیل آن‌ها استفاده می‌کند. همچنین بخش تحلیل گراف با **Neo4j Graph Data Science (GDS)** ارائه شده است.

## معماری کلی

```text
Neo4j ── Cypher / GDS ── Python ── Pandas · Pyvis · Plotly ── Streamlit
```

## امکانات

- داشبورد با آمار گراف، تعداد گره‌ها و رابطه‌ها
- نمایش تعاملی گراف و مرور گره‌ها و رابطه‌ها
- جست‌وجوی موجودیت‌ها و رابطه‌ها
- گسترش گراف از طریق گره‌های مرتبط و بررسی مسیرها
- نمایش خط زمانی رویدادها
- مشاهده‌ی صفحات ویکی‌پدیا و منابع مرتبط
- تحلیل گراف با GDS، از جمله PageRank، سنجه‌های مرکزیت، تشخیص اجتماع و شباهت گره‌ها
- کنسول اجرای پرس‌وجوهای Cypher برای مدیران
- ورود و بازبینی داده‌های ویکی‌پدیا از طریق رابط مدیریتی
- ابزارهای مدیریت کاربران، موضوع‌ها و فرایندهای ورود داده
- ابزار Entity Resolution برای شناسایی و بررسی موجودیت‌های احتمالاً تکراری

## ساختار داده در Neo4j

گره‌ها بر اساس نوع موجودیت برچسب می‌گیرند؛ برای نمونه `Person`، `Location`، `Organization`، `Event` و `Time`. ویژگی‌های گره می‌توانند شامل `name` و اطلاعات منبع باشند.

رابطه‌ها با برچسب `RELATION` ذخیره می‌شوند و نوع رابطه در ویژگی `type` قرار می‌گیرد. اطلاعات منبع نیز، در صورت وجود، همراه گره‌ها و رابطه‌ها نگهداری می‌شود.

## بازیابی پایگاه داده‌ی Neo4j از فایل Dump

این پروژه برای آماده‌سازی گراف موجود، از **فایل پشتیبان Neo4j با پسوند `.dump`** استفاده می‌کند؛ در این مسیر، فایل JSON ورودی روش بازیابی پایگاه داده نیست.

1. Neo4j Desktop را نصب و اجرا کنید.
2. یک DBMS محلی سازگار با نسخه‌ی پایگاه داده‌ی موجود در فایل dump ایجاد یا انتخاب کنید.
3. از ابزار بازیابی/بارگذاری فایل dump در Neo4j Desktop استفاده کنید و فایل `.dump` را انتخاب کنید. نام پایگاه داده‌ی مقصد را مشخص کنید و مراحل نمایش‌داده‌شده را تا پایان دنبال کنید.
4. پایگاه داده‌ی بازیابی‌شده را اجرا کنید و از Neo4j Browser مطمئن شوید که گراف و داده‌های مورد انتظار در دسترس هستند.
5. نشانی اتصال، نام کاربری، رمز عبور و نام پایگاه داده را در تنظیمات برنامه قرار دهید.

**نکته:** فایل dump باید با نسخه‌ی Neo4j مقصد سازگار باشد. پیش از جایگزین‌کردن پایگاه داده‌ی موجود، از اطلاعات فعلی نسخه‌ی پشتیبان بگیرید. بازیابی dump، پایگاه داده را برمی‌گرداند؛ این کار با واردکردن JSON از طریق کد برنامه تفاوت دارد.

## تنظیم متغیرهای محیطی

از فایل `.env.example` یک کپی با نام `.env` بسازید و مقادیر مورد نیاز را وارد کنید:

```dotenv
NEO4J_URI=bolt://localhost:7687
NEO4J_USERNAME=neo4j
NEO4J_PASSWORD=your_password
NEO4J_DATABASE=neo4j

AUTH_ENABLED=true
DEV_MACHINE_NAME=YOUR-PC-NAME
MAIN_ADMIN_USERNAME=mainadmin
MAIN_ADMIN_PASSWORD=change_me

ALLOW_GDS_WRITEBACK=false
GROQ_API_KEY=your_groq_api_key
GROQ_MODEL=qwen/qwen3.8-27b
ALLOW_WIKI_IMPORT=true
AUTO_PIPELINE_ON_APPROVE=true
ALLOW_GRAPH_MERGE=false
```

مقادیر را متناسب با محیط خود تنظیم کنید. برای اجرای محلی، `NEO4J_URI` معمولاً به سرویس Neo4j محلی اشاره می‌کند؛ برای Neo4j Aura باید نشانی اتصال ارائه‌شده در پنل Aura را وارد کنید.

کلیدهای API، رمزهای عبور و فایل `.env` را در مخزن عمومی GitHub قرار ندهید. فایل `.env.example` فقط برای نشان‌دادن نام تنظیمات است و نباید حاوی اطلاعات محرمانه‌ی واقعی باشد.

## اجرای برنامه

پس از اجرای Neo4j و تنظیم اتصال، از ریشه‌ی پروژه اجرا کنید:

```bash
streamlit run app.py
```

Streamlit نشانی محلی برنامه را در ترمینال نمایش می‌دهد؛ آن را در مرورگر باز کنید.

## بخش‌های برنامه

| بخش | کاربرد |
|---|---|
| Dashboard | نمایش آمار کلی گراف |
| Bloom | مرور و نمایش تعاملی گراف، جست‌وجو، فیلتر و گسترش گره‌ها |
| جست‌وجوی Entity/Relation | جست‌وجوی موجودیت‌ها و رابطه‌ها |
| Timeline | نمایش رویدادهای دارای تاریخ قابل‌شناسایی |
| Sources | مرور صفحات منبع ویکی‌پدیا و اطلاعات مرتبط |
| Graph Analytics (GDS) | اجرای الگوریتم‌های تحلیل گراف |
| Query Console | اجرای پرس‌وجوهای Cypher برای کاربران مجاز |
| مدیریت | مدیریت کاربران و موضوع‌ها و دسترسی به ابزارهای مدیریتی |
| Wiki Import | دریافت، استخراج و بازبینی داده‌های ویکی‌پدیا |
| Entity Resolution | بررسی موجودیت‌های مشکوک به تکراری‌بودن و مدیریت فرایند ادغام |

برخی بخش‌ها بر اساس نقش کاربر در دسترس قرار می‌گیرند.

## ورود داده از ویکی‌پدیا

در بخش مدیریتی Wiki Import، مدیر می‌تواند عنوان صفحه‌های ویکی‌پدیا را وارد کند، داده‌های استخراج‌شده را بررسی کند و ردیف‌های نامعتبر را پیش از تأیید کنار بگذارد. در صورت فعال‌بودن خط لوله‌ی خودکار، پس از تأیید درخواست، دریافت صفحه و استخراج اطلاعات اجرا می‌شود. افزودن داده به گراف نیازمند تأیید نهایی در رابط برنامه است.

برای قابلیت استخراج مبتنی بر Groq، مقدار `GROQ_API_KEY` باید در تنظیمات محیط قرار گرفته باشد. خروجی مدل را پیش از تأیید نهایی بررسی کنید؛ استخراج خودکار تضمین نمی‌کند که همه‌ی موجودیت‌ها و رابطه‌ها بدون خطا باشند.

## تحلیل گراف با GDS

برای استفاده از تحلیل‌های GDS، افزونه‌ی **Neo4j Graph Data Science** را برای پایگاه داده‌ی خود نصب و فعال کنید. در محیط‌هایی که GDS در دسترس نیست، صفحات تحلیل مربوط به آن قابل استفاده نخواهند بود؛ سایر قابلیت‌های برنامه که به GDS وابسته نیستند می‌توانند جداگانه کار کنند.

## استقرار در Streamlit Community Cloud

1. مخزن را در GitHub قرار دهید.
2. برنامه را در Streamlit Community Cloud به مخزن متصل کنید و `app.py` را به‌عنوان فایل اصلی انتخاب کنید.
3. اطلاعات اتصال Neo4j و کلیدهای موردنیاز را در بخش **Secrets** تنظیم کنید.
4. مطمئن شوید پایگاه داده‌ی Neo4j از محیط استقرار قابل دسترسی است.

فایل‌های محلی مانند داده‌های کاربران یا mailbox ممکن است در محیط‌های میزبانی‌شده ماندگار نباشند. برای استفاده‌ی عمومی، روش ذخیره‌سازی پایدار، احراز هویت و مجوزهای دسترسی را متناسب با نیاز خود پیکربندی کنید.
